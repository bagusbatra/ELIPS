## 1. Ringkasan Eksekutif

ELIPS LMS telah mencapai tahap **demo fungsional end-to-end**. Seluruh alur bisnis utama sudah diterapkan: Admin membuat kursus Draft, menugaskan instruktur, menugaskan peserta, instruktur mengelola materi dan memberi nilai, sistem membuat sertifikat Draft, lalu Admin menyetujui sertifikat menjadi Publish dan dapat diverifikasi publik.

Pada periode ini fokus pengembangan berada pada **perapian arsitektur dan peningkatan pengalaman Admin**, dengan capaian terbaru:

1. **Modularisasi JavaScript** menjadi 15 modul dengan satu lapisan CRUD/business logic terpusat.
2. **Audit trail (P1)** untuk perubahan kursus, pengguna, penugasan, konten, nilai, dan sertifikat.
3. **Notifikasi email simulasi (P2)** melalui outbox `localStorage`, dengan halaman admin untuk filter, ekspor CSV, dan pembersihan.
4. **Modal pilihan role Tambah Pengguna** — Admin, Instruktur, atau Peserta — sebelum mengisi form pengguna.

Seluruh rangkaian pengujian regresi terakhir **lulus tanpa error**.

### 2.2 Modal Pilihan Role Tambah Pengguna (v1.8)

**Kebutuhan:** saat Admin menekan **Tambah Pengguna**, sistem harus lebih dulu menampilkan pilihan jenis akun.

**Implementasi:**

- Tombol **Tambah Pengguna** pada `admin/users.html` memanggil `openUserTypeModal()`.
- Modal pertama menampilkan 3 tombol pilihan:
  - **Admin** — akses penuh pengelolaan sistem dan persetujuan sertifikat.
  - **Instruktur** — mengelola modul/materi dan memberi nilai pada kursus yang diampu.
  - **Peserta** — mengikuti kursus yang ditugaskan dan melihat sertifikat terbit.
- `chooseUserRole(role)` menutup modal pilihan, membuka form pengguna, mempreset role, dan menyesuaikan judul form (mis. “Tambah Instruktur”).
- `openUserModal(userId, presetRole)` tetap mendukung alur edit pengguna tanpa perubahan perilaku.
- Style `.user-role-choice` ditambahkan ke `assets/css/style.css`.

**Dampak:** Admin tidak lagi masuk ke form kosong; role dipilih lebih dulu namun tetap dapat diubah melalui dropdown sebelum disimpan. API CRUD tidak berubah.

### 2.3 Notifikasi Email Simulasi (v1.7)

- Outbox tersimpan pada `elips_notifications` (maksimal 1000 entri).
- Notifikasi dibuat saat kursus dipublikasikan (peserta aktif + instruktur aktif) dan saat sertifikat disetujui (peserta).
- Halaman `admin/notifications.html` menyediakan statistik, filter jenis/penerima/tanggal/pencarian, detail isi, ekspor CSV, dan pembersihan outbox.
- Catatan: ini **simulasi**, bukan pengiriman email nyata.

### 2.4 Audit Trail (v1.6/P1)

- `assets/js/audit.js` mencatat aktor, aksi, entitas, waktu, dan detail perubahan.
- Halaman `admin/audit.html` menyediakan statistik aktivitas, filter aktor/aksi/entitas/tanggal/pencarian, ekspor CSV, dan pembersihan log.
- Resolusi aktor: `actorId` eksplisit → user sesi → “Sistem”.

### 2.5 Modularisasi JavaScript (v1.5/P0)

- Seluruh CRUD dan aturan bisnis dipusatkan di `window.ELIPS`.
- Setiap fungsi CRUD mengembalikan `{ ok, message, data }`.
- Halaman hanya menangani rendering dan interaksi UI; tidak menulis langsung ke `localStorage`.
- Sertifikat Draft sepenuhnya disembunyikan dari peserta.

## 4. Fitur yang Sudah Selesai

### 4.1 Autentikasi & Hak Akses
- Login dengan validasi terhadap `elips_users`.
- Redirect otomatis sesuai role.
- Role guard pada setiap halaman dashboard (`ELIPS.requireRole()`).
- Struktur folder terpisah per role.

### 4.2 Manajemen Kursus
- Daftar kursus publik (hanya status Published).
- Detail kursus dengan tombol enrolment dinamis.
- Tambah/edit kursus; kursus baru selalu Draft.
- Penugasan 1 instruktur per kursus (penugasan ulang menggantikan instruktur lama).
- Validasi publikasi: wajib instruktur aktif serta memiliki modul/materi.
- Publikasi/tarik kursus kembali ke Draft oleh Admin.

### 4.3 Pengguna & Penugasan
- CRUD pengguna dengan filter role dan pencarian.
- Modal pilihan role saat menambah pengguna (baru).
- Penugasan instruktur ke kursus.
- Penugasan peserta ke satu atau beberapa kursus.
- Aktivasi/nonaktivasi enrollment.
- Penghapusan instruktur otomatis melepas kursus dan mengembalikannya ke Draft.

### 4.4 Konten & Pembelajaran
- CRUD modul dan materi (teks, video, file, link eksternal).
- Validasi kepemilikan konten oleh instruktur.
- Pembelajaran berurutan; pelajaran berikutnya terkunci sampai sebelumnya selesai.
- Mode pratinjau untuk Admin/Instruktur tanpa mengubah progres peserta.
- Tracking `elips_completedLessons`.

### 4.5 Penilaian & Sertifikat
- Input nilai 0–100 dengan konversi grade A–E dan catatan.
- Nilai otomatis membuat/memperbarui e-sertifikat Draft.
- Sertifikat Draft tidak tampil dan tidak dapat diverifikasi peserta.
- Admin menyetujui Draft → Publish; nomor final dan tanggal approval disimpan.
- Sertifikat Publish tampil di halaman peserta dan dapat diverifikasi publik.

### 4.6 Operasional Admin
- Dashboard statistik.
- Laporan progres peserta per kursus (ekspor PDF/Excel masih berupa UI).
- Pengaturan umum, sertifikat, dan pembelajaran.
- Audit trail dengan filter dan ekspor CSV.
- Outbox notifikasi dengan filter dan ekspor CSV.

## 7. Risiko & Keterbatasan

| Risiko/Keterbatasan | Dampak | Rekomendasi |
|---|---|---|
| Data hanya di `localStorage` | Tidak sinkron antar perangkat/browser; rawan hilang jika cache dibersihkan | Migrasi ke backend + database |
| Belum ada backend/API | Tidak cocok untuk multi-pengguna nyata | Sediakan REST API dan autentikasi server |
| Password disimpan di sisi klien | Tidak aman | Gunakan hashing (bcrypt/argon2) di server |
| Otorisasi hanya di sisi klien | Dapat dimanipulasi | Terapkan RBAC di server |
| Email masih simulasi | Pengguna tidak menerima email nyata | Integrasikan SMTP/email service |
| Ekspor laporan PDF/Excel baru UI | Belum menghasilkan file nyata | Implementasikan library ekspor atau endpoint |
| Aset CDN memerlukan internet | Tampilan ikon/font bisa terganggu offline | Self-host font dan ikon |
| Belum ada pengujian otomatis di CI | Regresi bergantung uji manual | Tambahkan pipeline CI |

---

## 8. Rencana Selanjutnya

### Prioritas Tinggi
1. **Backend & database** — pindahkan data dari `localStorage` ke API + database relasional.
2. **Autentikasi aman** — hashing password, sesi/token server, dan RBAC server-side.
3. **Integrasi email nyata** — ganti outbox simulasi dengan pengiriman email sesungguhnya.

### Prioritas Menengah
4. **Ekspor laporan nyata** — PDF/Excel untuk laporan progres dan sertifikat.
5. **Peningkatan aksesibilitas** — navigasi keyboard, ARIA pada modal, kontras warna.
6. **Pengujian otomatis di CI** — jalankan suite regresi pada setiap push.

### Prioritas Rendah
7. **Self-host aset** — font dan ikon agar tidak bergantung CDN.
8. **Peningkatan UX** — pencarian global, pagination tabel, dan notifikasi in-app.

---

## 9. Cara Menjalankan

1. Buka `index.html` pada browser modern (Chrome/Edge/Firefox).
2. Login menggunakan akun demo (mis. Admin ID 1) melalui `login.html`.
3. Data demo akan di-seed otomatis ke `localStorage` pada kunjungan pertama.
4. Untuk mengulang dari kondisi awal, hapus key `elips_*` pada Application → Local Storage, lalu muat ulang halaman.

## 10. Kesimpulan

ELIPS LMS berada pada kondisi **stabil untuk demo**: seluruh alur utama berjalan, arsitektur JavaScript sudah modular, audit trail dan notifikasi simulasi aktif, serta pengalaman Admin dalam menambah pengguna meningkat melalui modal pilihan role. Seluruh pengujian regresi lulus.

Langkah berikutnya yang paling menentukan adalah migrasi ke backend dengan penyimpanan terpusat dan autentikasi yang aman, karena keterbatasan `localStorage` menjadi batas utama untuk penggunaan produksi.
