## 1. Ringkasan Eksekutif

Sejak laporan 3 November 2026, ELIPS LMS mengalami perubahan arsitektur yang paling signifikan: aplikasi tidak lagi hanya berupa demo `localStorage`, tetapi sudah memiliki **backend PHP 8 + MySQL 8** dengan autentikasi sesi, otorisasi server-side, audit trail, dan outbox notifikasi yang tersimpan di database. Backend v3.0 selesai pada 4 November 2026 dan seluruh alur v3.0 tetap dipertahankan.

Di atas fondasi tersebut, **v4.0 Phase 1–2** telah diimplementasikan pada 5 November 2026:

1. **Versi kurikulum** per kursus dengan status `draft → published → locked → retired`, mekanisme clone, dan penguncian otomatis saat kelas dibuat.
2. **Kelas/angkatan** dengan satu tentor aktif, histori pergantian tentor, kuota, periode, serta status penyelenggaraan.
3. **Enrollment berbasis kelas**, sehingga satu peserta dapat mengikuti kursus yang sama pada angkatan berbeda dengan nilai dan sertifikat terpisah.
4. **Halaman akademik Admin** (`admin/academic.html`) untuk mengelola versi kurikulum, kelas, tentor, roster, dan struktur kurikulum.
5. **Dukungan dual-mode penuh** — aturan v4 diterapkan di server melalui API dan di mode lokal melalui `assets/js/crud-academic.js`.

Seluruh pengujian regresi lokal dan server lulus tanpa error. Working tree bersih dan Increment Phase 1–2 sudah di-commit.

### 2.2 Backend PHP 8 + MySQL 8 (v3.0)

Backend v3.0 menggantikan ketergantungan tunggal pada `localStorage`:

- **API front controller** di `api/index.php` dengan 39 aksi bisnis di `api/actions.php`.
- **Autentikasi sesi PHP native** (`$_SESSION`) dengan cookie `HttpOnly` dan `SameSite=Lax`.
- **Password aman** menggunakan `password_hash()` dan `password_verify()`; hash tidak pernah dikirim ke client.
- **Otorisasi server-side** untuk role dan kepemilikan: instruktur hanya mengelola kursus/kelas yang diampu, peserta hanya mengubah progres miliknya, dan aksi administratif hanya untuk Admin.
- **Snapshot API** yang menghidrasi cache client setelah login dan setiap operasi tulis, sehingga UI tetap sinkron tanpa reload.
- **Sanitasi HTML allowlist** di server untuk materi bertipe teks.
- **Audit trail dan notifikasi** yang ditulis backend ke MySQL, bukan hanya di browser.
- **Installer** `api/install.php` untuk membuat database, skema, dan data demo secara idempoten.

### 2.5 v4.0 Phase 1 — Versi Kurikulum

Model kursus dipisahkan dari struktur kontennya:

- Tabel baru `curriculum_versions` menyimpan versi per kursus dengan kode unik (mis. `1.0`, `2.0`).
- `modules` dan `lessons` sekarang wajib memiliki `curriculum_version_id`.
- Status versi: `draft`, `published`, `locked`, `retired`.
- Versi baru selalu `draft`; hanya versi `published`/`locked` yang dapat dipakai membuat kelas.
- Saat kelas dibuat, versi dikunci secara **transaksional** (`FOR UPDATE`) sehingga konten tidak dapat berubah di tengah proses.
- Versi `locked`/`retired` menolak create/update/delete modul dan materi.
- Revisi dilakukan dengan **clone** ke Draft baru; versi yang sudah dipakai tidak dihapus, tetapi dapat **dipensiunkan** (`retired`).
- Hanya versi `draft` tanpa kelas yang boleh dihapus.
- Snapshot hanya mengekspos modul/materi dari versi aktif (non-retired) tiap kursus; struktur versi lengkap diambil melalui `curriculum.detail`.

Aksi API baru: `curriculum.create`, `curriculum.update`, `curriculum.publish`, `curriculum.clone`, `curriculum.retire`, `curriculum.delete`, dan `curriculum.detail`.

### 2.6 v4.0 Phase 2 — Kelas, Tentor, dan Enrollment

- Tabel baru `classes` dan `class_instructor_histories`.
- Kelas menyimpan kode unik, nama, kursus, versi kurikulum, tentor, periode, kuota, lokasi/ruang, catatan jadwal, JP rencana, dan status.
- **Satu kelas = satu tentor aktif**; satu tentor boleh mengampu banyak kelas.
- Pergantian tentor dicatat sebagai histori: entri lama ditutup (`ended_at`), entri baru dibuka; penugasan tentor yang sama bersifat idempoten.
- Status kelas: `draft`, `open`, `ready`, `ongoing`, `completed`, `cancelled`, `archived`.
- Kuota dicek saat pendaftaran dan tidak boleh diturunkan di bawah jumlah peserta aktif.
- Kelas dengan enrollment tidak dapat dihapus.
- `enrollments` mendapat `class_id` dan status diperluas (`pending`, `active`, `completed`, `withdrawn`, `suspended`, `cancelled`, `dihentikan`).
- Unique key berubah menjadi `(student_id, class_id)`, sehingga peserta dapat terdaftar di beberapa angkatan untuk kursus yang sama.
- Nilai dan sertifikat memakai unique per `enrollment_id`, bukan per `(student_id, course_id)`.
- Enrollment v3 dipetakan ke kelas migrasi `ANG-2026-MNJ-01` (`legacy_import = 1`) agar tidak ada data yang hilang.

Aksi API baru: `class.create`, `class.update`, `class.status`, `class.assignInstructor`, `class.delete`, `enrollment.assignClass`, dan `enrollment.classStatus`.

### 2.7 Dukungan Client dan UI Akademik

- `assets/js/crud-academic.js` (baru) menerapkan aturan kurikulum/kelas yang sama pada mode lokal, termasuk penguncian versi, clone, retire, histori tentor, kuota, dan roster.

- `admin/academic.html` (baru) menyediakan:

  - tabel kelas dengan detail, edit, status, dan penugasan tentor;

- Navigasi `academic.html` ditambahkan ke seluruh halaman Admin.
- `instructor/dashboard.html` menampilkan tabel **“Kelas yang Diampu”**.

## 4. Fitur yang Sudah Selesai

### 4.1 Autentikasi & Hak Akses
- Login dengan verifikasi password hash di server.
- Sesi PHP native dengan cookie `HttpOnly`/`SameSite=Lax`.
- Redirect otomatis sesuai role.
- Role guard di halaman dan pengecekan role/kepemilikan di setiap aksi API.
- Fallback mode lokal tetap tersedia untuk demo dan pengujian JSDOM.

### 4.2 Manajemen Kursus & Kurikulum
- Daftar kursus publik hanya menampilkan status Published.
- Kursus baru selalu Draft; publikasi divalidasi (instruktur aktif, modul, dan materi).
- Penugasan satu instruktur per kursus.
- Versi kurikulum: buat, ubah, publish, clone, retire, dan hapus Draft.
- Penguncian versi otomatis saat kelas dibuat.
- Penolakan perubahan pada versi Locked/Retired.
- Kategori kursus terstruktur.

### 4.3 Kelas/Angkatan & Tentor
- CRUD kelas dengan kode unik, periode, kuota, lokasi/ruang, catatan jadwal, dan JP rencana.
- Pemilihan versi kurikulum Published/Locked.
- Satu tentor aktif per kelas; satu tentor dapat mengampu banyak kelas.
- Histori pergantian tentor dengan alasan dan aktor.
- Status kelas `draft/open/ready/ongoing/completed/cancelled/archived`.
- Validasi periode dan kuota.
- Kelas dengan enrollment tidak dapat dihapus.

### 4.4 Pengguna & Enrollment
- CRUD pengguna dengan filter role dan pencarian.
- Modal pilihan role saat menambah pengguna.
- Pendaftaran peserta ke kelas melalui `admin/enrollment.html` atau roster `admin/academic.html`.
- Pendaftaran duplikat pada kelas yang sama dilewati (idempoten).
- Kuota kelas ditegakkan saat pendaftaran dan saat update kuota.
- Status enrollment `active/completed/withdrawn/cancelled` (plus status lama yang dinormalisasi).
- `withdrawn` mencabut akses tanpa menghapus riwayat nilai/sertifikat.

### 4.5 Konten & Pembelajaran
- CRUD modul dan materi (teks, video, file, link eksternal).
- Modul/materi terikat ke versi kurikulum.
- Validasi kepemilikan konten oleh instruktur.
- Penolakan perubahan pada versi Locked/Retired.
- Pembelajaran berurutan; materi berikutnya terkunci sampai sebelumnya selesai.
- Materi ditampilkan dari versi kurikulum yang terkunci pada kelas peserta.
- Mode pratinjau untuk Admin/Instruktur tanpa mengubah progres peserta.
- Tracking `completed_lessons`.

### 4.6 Penilaian & Sertifikat
- Input nilai 0–100 dengan konversi grade A–E dan catatan.
- Nilai terhubung ke enrollment, sehingga angkatan berbeda memiliki nilai terpisah.
- Nilai otomatis membuat/memperbarui e-sertifikat Draft.
- Sertifikat Draft tidak tampil dan tidak dapat diverifikasi peserta.
- Admin menyetujui Draft → Publish; nomor final dan tanggal approval disimpan.
- Sertifikat Publish tampil di halaman peserta dan dapat diverifikasi publik.

### 4.7 Operasional Admin
- Dashboard statistik.
- Laporan progres peserta per kursus (ekspor PDF/Excel masih berupa UI).
- Pengaturan umum, sertifikat, dan pembelajaran.
- Audit trail dengan filter dan ekspor CSV.
- Outbox notifikasi dengan filter dan ekspor CSV.
- Halaman akademik untuk kurikulum dan kelas.

## 5. Arsitektur Saat Ini

- **Frontend:** HTML5, CSS3 (custom properties), Vanilla JavaScript.
- **Backend:** PHP 8 native, tanpa framework.
- **Database:** MySQL 8, database `elips_lms`, 14 tabel InnoDB/utf8mb4.
- **Autentikasi:** sesi PHP native; password di-hash dengan `password_hash()`.
- **Lapisan data & bisnis:** `window.ELIPS` pada 18 modul `assets/js/`.
- **Mode data:**
  - **Server:** API + MySQL, snapshot cache di client.
  - **Lokal:** `localStorage` sebagai fallback demo/uji.
- **Struktur:** berbasis role (`admin/`, `instructor/`, `student/`) dan backend terpisah (`api/`).
- **Aset eksternal:** Google Fonts dan Bootstrap Icons CDN, sehingga memerlukan koneksi internet.

## 9. Cara Menjalankan

### 9.1 Mode Server (utama)

1. Pastikan MySQL 8 berjalan.
2. Dari root proyek, jalankan:

   ```powershell
   php api/install.php --fresh
   ```

3. Sajikan folder proyek:

   ```powershell
   php -S 127.0.0.1:8099 -t .
   ```

4. Buka `http://127.0.0.1:8099/` dan login dengan akun demo.
5. Untuk mereset data demo, ulangi langkah 2.

### 9.2 Mode Lokal (fallback/demo)

1. Buka `index.html` langsung di browser modern.
2. Data demo akan di-seed otomatis ke `localStorage`.
3. Untuk mereset, hapus seluruh key `elips_*` pada Application → Local Storage, lalu muat ulang.

## 10. Kesimpulan

ELIPS LMS telah beralih dari demo `localStorage` menjadi aplikasi **dual-mode dengan backend PHP 8 + MySQL 8** yang memiliki autentikasi server, otorisasi role/kepemilikan, audit trail, dan notifikasi tersimpan di database. Backend v3.0 stabil dan seluruh alur lamanya tetap berjalan.

Increment **v4.0 Phase 1–2** menambahkan fondasi akademik yang selama ini belum ada: versi kurikulum yang dapat direvisi tanpa merusak histori, kelas/angkatan dengan tentor dan kuota, serta enrollment yang memisahkan nilai dan sertifikat per angkatan. Halaman `admin/academic.html` dan dukungan mode lokal membuat fitur ini dapat digunakan dan diuji secara konsisten.

Dengan seluruh pengujian lulus dan working tree bersih, langkah berikutnya yang paling menentukan adalah **Phase 3: jadwal dan presensi offline**, diikuti Phase 4–8 sesuai roadmap v4.0.
