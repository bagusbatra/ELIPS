## 3. Phase 6 — Penilaian & Finalisasi Nilai

### 3.1 Tujuan

Phase 6 melengkapi alur penilaian v4.0: satu kelas memiliki **skema penilaian** berisi komponen berbobot (tugas, ujian, dan penilaian manual), nilai komponen dihitung menjadi nilai akhir, nilai yang belum lengkap ditandai `incomplete`, nilai yang sudah final dikunci, dan perubahan setelah finalisasi hanya dapat dilakukan melalui **koreksi beralasan yang tercatat**. Alur nilai manual klasik tetap dipertahankan untuk kompatibilitas.

### 3.2 Model data

Lima tabel baru:

| Tabel | Fungsi | Constraint utama |
|---|---|---|
| `predicate_ranges` | Rentang predikat huruf A–E global | `letter` UNIQUE; index (`sort_order`, `min_score`) |
| `grade_schemes` | Skema penilaian per kelas | `class_id` UNIQUE; FK ke kelas, kursus, pembuat/pembaru |
| `grade_scheme_components` | Komponen berbobot milik skema | FK `scheme_id` cascade; tipe `assignment`/`exam`/`manual` |
| `grade_component_scores` | Nilai per komponen per enrollment | UNIQUE(`component_id`, `enrollment_id`); status `not_assessed`/`graded`/`excused`/`missing` |
| `grade_corrections` | Jejak koreksi nilai finalized | FK `grade_id`, `enrollment_id`, `actor_id`; append-only |

Perluasan tabel `grades`:

- `scheme_id` — skema yang dipakai saat komputasi/finalisasi;
- `final_score` — nilai akhir desimal;
- `status` — `draft`, `incomplete`, `finalized`;
- `components_snapshot` — JSON komponen dan bobot saat finalisasi;
- `finalized_by`, `finalized_at`, `computed_at` — jejak finalisasi dan komputasi.

Seed demo menambahkan 9 predikat default (A 90–100 … E 0–49.99), satu skema published untuk kelas 1, tiga komponen (tugas 30%, ujian 40%, manual 30%), dan nilai komponen manual untuk enrollment 1–2. Koleksi koreksi sengaja kosong.

### 3.3 Backend dan API

Dua belas aksi baru:

- **Predikat:** `predicate.list`, `predicate.save`.
- **Skema:** `gradeScheme.list`, `gradeScheme.save`, `gradeScheme.status`, `gradeScheme.delete`.
- **Nilai:** `grade.roster`, `grade.manualSave`, `grade.exempt`, `grade.finalize`, `grade.correct`, `grade.transcript`.

Aturan server utama:

- Hanya **Admin** yang dapat mengubah predikat. Himpunan rentang aktif wajib menutup 0–100 tanpa celah dan tanpa tumpang tindih.
- Hanya **Admin atau instruktur pemilik kelas** yang dapat mengelola skema, menilai komponen, memfinalisasi, dan mengoreksi.
- Publikasi skema mensyaratkan minimal satu komponen dan total bobot tepat **100%**.
- Skema `published`/`archived` tidak dapat kembali ke `draft` atau dihapus; harus diarsipkan lalu diganti.
- `grade.save` dan `grade.manualSave` menolak perubahan nilai yang sudah `finalized`.
- `grade.finalize` menolak nilai `incomplete`, menulis snapshot komponen, dan mengunci nilai.
- `grade.correct` hanya untuk nilai finalized, wajib alasan minimal 5 karakter, dan menulis baris `grade_corrections` dalam transaksi yang sama.
- `grade.transcript` hanya mengembalikan transkrip milik peserta yang login; instruktur/Admin pengampu dapat membaca roster kelas yang dikelola.

Logika komputasi:

```text
if ada komponen wajib tanpa nilai:
    status = incomplete
else:
    bobot_dihitung = bobot komponen wajib + opsional yang memiliki nilai
    final_score = Σ(skor × bobot) / Σ(bobot_dihitung)
    final_score = bulatkan(final_score, rounding skema)
    grade = predicateLetter(final_score)
```

Komponen `excused` dan komponen opsional kosong dikeluarkan dari perhitungan, lalu bobot dinormalisasi ulang. Nilai `0` hanya dihitung bila benar-benar diisi.

### 3.4 Mode lokal

- Lima key baru: `elips_predicateRanges`, `elips_gradeSchemes`, `elips_gradeSchemeComponents`, `elips_gradeComponentScores`, `elips_gradeCorrections` (total 38 key).
- `assets/js/data.js` menambahkan aksesor koleksi, `predicateLetter()`, `gradeRound()`, `gradeWeightTotal()`, dan `computeEnrollmentGrade()`.
- `assets/js/crud-grades.js` menyediakan paritas seluruh aksi Phase 6, termasuk guard published/archived, kunci finalisasi, pengecualian beralasan, koreksi dengan `actorName`, dan transkrip.
- `assets/js/seed.js` menambahkan predikat, skema/komponen demo, nilai manual, dan koleksi koreksi kosong.
- `assets/js/utils.js` menegaskan `gradeLetter()` memakai predikat aktif, bukan tabel hardcoded.
- `assets/js/audit.js` menambahkan label `finalize`, `exempt`, `predicate`, `grade_scheme`, dan `grade_component`.

### 3.5 UI

- **Instruktur (`instructor/students.html`):** editor skema dan komponen berbobot, panel roster/nilai/finalisasi, modal pengecualian, dan modal koreksi beralasan. Opsi Draft dinonaktifkan untuk skema non-draft.
- **Admin (`admin/settings.html`):** editor predikat A–E dengan validasi cakupan 0–100, tambah/hapus baris, reset default, dan simpan.
- **Peserta (`learning.html`):** panel transkrip berisi nilai akhir, huruf, status, tabel komponen/aktivitas, peringatan komponen kosong, dan riwayat koreksi.

### 3.6 Aturan bisnis

- Nilai akhir berbobot, bukan rata-rata nilai mentah.
- Komponen wajib kosong menghasilkan `incomplete`; nilai kosong tidak pernah menjadi 0 implisit.
- Huruf dihitung dari predikat aktif; perubahan predikat berlaku pada komputasi/transkrip berikutnya.
- Satu kelas hanya memiliki satu skema; skema terbit/arsip terkunci.
- Nilai finalized terkunci; koreksi wajib alasan dan tercatat append-only.
- Finalisasi **tidak** membuat sertifikat otomatis; alur sertifikat Draft → Publish tetap Phase 7.

## 7. Risiko dan Keterbatasan

| Risiko/Keterbatasan | Dampak | Rekomendasi |
|---|---|---|
| Finalisasi tidak membuat sertifikat otomatis | Peserta harus menunggu alur sertifikasi Phase 7 | Definisikan pemicu sertifikasi dari nilai finalized pada phase berikutnya |
| Mode lokal tanpa transaksi | Finalisasi/koreksi yang gagal di tengah dapat meninggalkan data parsial | Gunakan mode server untuk operasi final; pertimbangkan jurnal lokal |
| Satu skema per kelas | Perubahan kebijakan penilaian harus lewat arsip + skema baru | Dokumentasikan prosedur pergantian skema |
| Bobot legacy pada tugas/ujian | Ada dua sumber bobot (kolom legacy dan komponen skema) | Gunakan komponen skema sebagai acuan; pertimbangkan deprecasi bobot legacy |
| Aturan absensi harian hanya di UI | API langsung masih dapat membuat duplikat `in/out` | Tambahkan unique index/guard transaksional |
| Foto absensi base64 di MySQL | Tabel membesar dan transfer data berat | Pindahkan ke object storage |
| Belum ada rate limiting, CSRF token, HTTPS wajib | Permukaan serangan belum tertutup penuh | Hardening sebelum produksi |
| Mode lokal tidak aman untuk produksi | Password demo diverifikasi di client | Gunakan hanya untuk demo/uji |
| Berkas tugas/materi hanya metadata/path | Belum ada upload/penyajian biner | Tambahkan endpoint upload dan kontrol unduh |

## 8. Rencana Selanjutnya

1. **Phase 7 — Sertifikasi:** hubungkan nilai `finalized` ke penerbitan sertifikat, nomor sertifikat, dan generate PDF.
2. **Penyempurnaan penilaian:** aksi penilaian massal, ekspor roster/transkrip, dan rekap nilai per kelas.
3. **Hardening:** rate limiting login, CSRF token, HTTPS wajib, rotasi session ID, dan pembatasan snapshot per role.
4. **Penyempurnaan absensi:** unique index/guard transaksional, reverse geocoding, rekap kehadiran, dan kaitan payroll.
5. **CI/CD:** jalankan seluruh suite lokal dan server pada setiap push, termasuk `api-phase5`, `api-phase6`, `local-phase5`, `local-phase6`, dan suite absensi.
6. **Kebersihan riwayat commit:** gunakan pesan commit konvensional agar setiap increment mudah dilacak.
