## 1. Ringkasan Eksekutif

Increment 6 November 2026 menambahkan **cabang** sebagai konteks penyelenggaraan kelas dan jadwal, serta menyediakan **halaman kalender/jadwal Admin** yang dapat difilter per cabang dan kelas. Perubahan bersifat aditif: skema, API, mode lokal, dan UI lama tetap berjalan, sedangkan data v3/v4 yang belum memiliki cabang tetap valid.

Cakupan utama increment:

1. **Tabel `branches`** dengan kode unik, nama, alamat, kota, telepon, manajer, status, dan catatan.
2. **Relasi opsional `classes.branch_id`** dengan FK `ON DELETE SET NULL`, sehingga kelas lama tidak wajib memiliki cabang.
3. **CRUD cabang di pengaturan Admin** (`admin/settings.html`) untuk tambah, ubah, aktif/nonaktif, dan hapus.
4. **Penugasan cabang pada kelas** di `admin/academic.html`, termasuk filter cabang dan kolom cabang.
5. **Halaman `admin/schedule.html`** berisi filter cabang/kelas, kalender bulanan, agenda harian, ringkasan bulan, tabel jadwal, dan modal detail sesi.
6. **Dukungan dual-mode penuh** — aturan cabang diterapkan di server melalui API dan di mode lokal melalui `assets/js/crud-academic.js`.

Seluruh pengujian regresi yang relevan lulus. Perubahan ini belum memecah alur akademik yang sudah ada: jadwal tetap dibuat/diubah dari halaman akademik, sedangkan halaman kalender berfungsi sebagai tampilan baca yang terorganisasi per cabang.

Pada tanggal yang sama, increment **Phase 4 — Materi dan Akses Kelas** juga diselesaikan. Phase 4 menghubungkan materi kurikulum ke kelas, menambahkan materi tambahan di luar kurikulum, menerapkan empat mode akses (`open`, `sequential`, `scheduled`, `conditional`), mencatat progres per enrollment, dan mendukung persetujuan instruktur serta file privat. Rincian lengkap ada di **§13**; ringkasan cabang/kalender tetap di §1–§12.

## 2. Latar Belakang dan Tujuan

Sebelum increment ini, kelas hanya menyimpan informasi kursus, versi kurikulum, tentor, periode, kuota, dan lokasi/ruang. Admin belum memiliki cara standar untuk:

- mengelompokkan kelas berdasarkan unit/cabang penyelenggara;
- melihat jadwal seluruh kelas dalam satu kalender;
- memfilter jadwal berdasarkan cabang atau kelas.

Increment ini menjawab kebutuhan tersebut tanpa mengubah model akademik inti. Cabang diperlakukan sebagai **atribut opsional** pada kelas, bukan pemilik data akademik. Dengan demikian:

- kelas lama tetap valid tanpa cabang;
- penghapusan cabang tidak menghapus kelas (FK `SET NULL`);
- aplikasi tetap menolak penghapusan cabang yang masih dipakai kelas agar data tidak kehilangan konteks secara tidak sengaja;
- sesi pertemuan memperoleh informasi cabang melalui kelasnya, bukan menyimpan FK cabang baru.

## 3. Model Data Cabang

### 3.1 Tabel `branches`

| Kolom | Tipe | Keterangan |
|---|---|---|
| `id` | `INT UNSIGNED` PK | ID cabang |
| `code` | `VARCHAR(40)` UNIQUE | Kode cabang, dibuat otomatis bila kosong (`CBG-...`) |
| `name` | `VARCHAR(150)` | Nama cabang |
| `address` | `VARCHAR(255)` | Alamat |
| `city` | `VARCHAR(100)` | Kota |
| `phone` | `VARCHAR(40)` | Telepon |
| `manager` | `VARCHAR(150)` | Penanggung jawab |
| `status` | `ENUM('active','inactive')` | Status cabang |
| `notes` | `TEXT` | Catatan |
| `created_at` / `updated_at` | `DATETIME` | Timestamp |

Index: `uq_branches_code` (UNIQUE), `idx_branches_status`, `idx_branches_city`.

### 3.2 Relasi ke kelas

- `classes.branch_id` nullable, index `idx_classes_branch`, FK `fk_classes_branch` ke `branches.id` dengan `ON DELETE SET NULL`.
- Cabang **wajib berstatus `active`** saat dipilih untuk kelas baru/perubahan kelas.
- Kelas lama tanpa cabang tetap valid (`branch_id = NULL`).
- Sesi pertemuan tidak memiliki kolom `branch_id` fisik. Mode server memperoleh field cabang melalui JOIN ke `classes`/`branches`; mode lokal menyimpan field cabang denormalisasi pada sesi dan menyinkronkannya saat cabang atau kelas berubah.

## 4. Perubahan Backend

### 4.1 Skema dan Installer

- `api/schema.sql` menambahkan tabel `branches`, kolom `classes.branch_id`, index, dan FK.
- `api/install.php`:
  - menambahkan kolom/index/FK secara aditif untuk database lama;
  - mengisi seed 3 cabang: `CBG-JKT` Jakarta, `CBG-BDG` Bandung, `CBG-SBY` Surabaya;
  - menetapkan kelas migrasi `ANG-2026-MNJ-01` ke cabang Jakarta;
  - memperbaiki indeks seed histori kelas agar konsisten setelah penambahan kolom.
- `php api/install.php --fresh` berhasil dan menghasilkan database seed yang bersih.

### 4.2 Helper dan Serializer

- `api/helpers.php` menambahkan serializer cabang (`elips_branch_row`, `elips_branch_public`).
- Serializer kelas memuat `branchId`, `branchCode`, `branchName`, dan `branchCity`.
- Serializer sesi memuat field cabang yang sama; query sesi mem-JOIN kelas dan cabang.
- Snapshot tetap tidak pernah memuat hash password.

### 4.3 Aksi API

Aksi baru:

- `branch.create`
- `branch.update`
- `branch.status`
- `branch.delete`

`class.create` dan `class.update` sekarang memvalidasi `branchId` (harus ada dan `active`) lalu menyimpan `branch_id`. Total aksi API menjadi **53**.

Aturan server-side:

- hanya Admin yang dapat mengelola cabang;
- kode cabang duplikat ditolak;
- kode kosong dibuat otomatis;
- penghapusan cabang ditolak bila masih ada kelas yang merujuknya;
- kelas tidak dapat diarahkan ke cabang `inactive`.

### 4.4 Snapshot

- `api/snapshot.php` menambahkan koleksi `branches`.
- Snapshot kelas menyertakan field cabang hasil JOIN.
- Snapshot sesi menyertakan field cabang melalui kelas.

- Cabang hanya dapat dikelola Admin.
- Kode cabang unik; kode kosong dibuat otomatis.
- Cabang `inactive` tidak dapat dipilih untuk kelas.

| Risiko/Keterbatasan | Dampak | Rekomendasi |

| Kalender belum tersinkron kalender eksternal | Tidak ada ekspor iCal/Google Calendar | Tambahkan integrasi pada phase berikutnya |

## 13. Increment Phase 4 — Materi dan Akses Kelas

### 13.1 Latar Belakang dan Tujuan

Phase 1–3 sudah memisahkan kursus dari kelas dan menyediakan jadwal/presensi. Namun materi masih melekat pada versi kurikulum saja, sehingga:

- kelas tidak dapat menambah bahan pendukung tanpa mengubah kurikulum;
- belum ada kebijakan kapan materi boleh dibuka peserta;
- progres belajar belum terikat ke enrollment/kelas;
- belum ada kontrol persetujuan instruktur atau perlindungan file privat.

Phase 4 menjawab kebutuhan tersebut secara aditif. Kurikulum tetap menjadi sumber materi utama; kelas memperoleh **pengaturan akses**, **materi tambahan**, dan **progres per enrollment**.

### 13.2 Model Data

Empat tabel baru ditambahkan ke `api/schema.sql`:

| Tabel | Fungsi | Constraint utama |
|---|---|---|
| `class_material_settings` | Kebijakan akses per kelas | `class_id` unik; FK cascade ke `classes`, `updated_by` SET NULL |
| `class_materials` | Materi tambahan kelas | FK ke `classes`, `lessons`, `class_sessions`; metadata file; status `active`/`hidden` |
| `class_lesson_progress` | Progres pelajaran per enrollment | UNIQUE(`enrollment_id`, `lesson_id`); cascade ke kelas/enrollment/pelajaran |
| `class_material_progress` | Progres materi tambahan per enrollment | UNIQUE(`enrollment_id`, `material_id`); cascade ke kelas/enrollment/materi |

Kelas yang belum memiliki baris `class_material_settings` memakai **default implisit** `accessMode = 'open'`, `requireInstructorApproval = false`, `id = null`. Default ini tidak dibuatkan baris sampai pengguna menyimpan pengaturan, sehingga perilaku server dan lokal identik serta data lama tetap kompatibel.

### 13.3 Aturan Akses

| Mode | Perilaku |
|---|---|
| `open` | Semua materi kurikulum aktif dapat dibuka peserta |
| `sequential` | Pelajaran ke-n terbuka setelah seluruh pelajaran sebelumnya selesai |
| `scheduled` | Pelajaran terbuka bila modulnya memiliki sesi non-`cancelled`/`no_show`/`rescheduled` yang tanggalnya sudah tiba |
| `conditional` | Prasyarat urutan **dan** tanggal sesi modul (bila ada) harus terpenuhi |

Aturan tambahan:

- Materi tambahan terkunci bila `status = hidden`, `available_from` belum tiba, pelajaran tertaut belum selesai, atau sesi tertaut belum tiba/dibatalkan.
- Peserta hanya menerima `content` untuk materi tidak terkunci; staf (Admin/instruktur pengampu) mendapat pratinjau tanpa mengubah progres peserta.
- Bila `require_instructor_approval` aktif, peserta ditolak saat menandai selesai; instruktur/Admin mengonfirmasi progres untuk enrollment.
- Perubahan pengaturan yang sudah tersimpan oleh Admin wajib `reason`; audit mencatat mode dan status persetujuan sebelum/sesudah.
- Perubahan status materi (`active`/`hidden`) wajib alasan dan dicatat audit.
- Snapshot hanya memuat metadata materi; `content` dan `file_path` tidak pernah dikirim.

### 13.4 Backend

- `api/helpers.php`: serializer pengaturan/materi/progres, query daftar materi, urutan pelajaran kurikulum, pencarian tanggal sesi modul, dan evaluator `elips_class_material_state()`.
- `api/actions.php`: delapan aksi baru — `material.settings`, `material.updateSettings`, `material.create`, `material.update`, `material.status`, `material.delete`, `material.classroom`, `material.progress`. Total aksi API menjadi **61**.
- Guard role: Admin semua kelas; instruktur hanya kelas yang diampu; peserta hanya enrollment miliknya.
- `api/snapshot.php`: koleksi `classMaterialSettings`, `classMaterials`, `classLessonProgress`, `classMaterialProgress`.
- `api/install.php`: seed lama tetap valid; kelas tanpa pengaturan memakai default implisit.

### 13.5 Mode Lokal

- Key baru: `elips_classMaterialSettings`, `elips_classMaterials`, `elips_classLessonProgress`, `elips_classMaterialProgress`.
- `assets/js/data.js`: accessor dan `isLessonCompleted()` yang membaca progres kelas + data legacy `elips_completedLessons`.
- `assets/js/seed.js`: normalisasi empat koleksi tanpa membuat baris pengaturan otomatis.
- `assets/js/crud-academic.js`: implementasi lokal pengaturan, CRUD/status materi, classroom, progres, dan evaluator kunci akses.
- `assets/js/audit.js`: label aksi `progress` dan entitas `class_material`/`class_material_settings`.

### 13.6 UI

- **Admin** (`admin/academic.html`): aksi **Akses materi** per kelas; modal mode/persetujuan dengan alasan wajib untuk override.
- **Instruktur** (`instructor/manage-course.html`): pemilih kelas, panel pengaturan akses, dan CRUD/status materi tambahan.
- **Peserta** (`learning.html`): daftar materi kelas, kunci akses, konten, tombol selesai, status persetujuan, dan materi tambahan di sidebar.

| File materi hanya metadata/path | Belum ada upload/penyajian biner | Tambahkan endpoint upload dan kontrol unduh |
| Mode `scheduled`/`conditional` bergantung jadwal sesi | Kelas tanpa sesi tidak membuka materi berbasis jadwal | Wajibkan jadwal modul sebelum aktivasi |
| Progres materi belum masuk nilai akhir | Nilai/sertifikat belum mempertimbangkan materi tambahan | Definisikan bobot pada Phase 5 |
| Persetujuan instruktur menambah beban manual | Instruktur harus mengonfirmasi tiap enrollment | Sediakan aksi konfirmasi massal pada increment berikutnya |

### 13.9 Kesimpulan Phase 4

Phase 4 melengkapi alur belajar v4.0 dari sisi materi: kelas kini memiliki kebijakan akses yang eksplisit, materi tambahan yang fleksibel, dan progres yang terikat pada enrollment. Implementasi menjaga kompatibilitas data lama, menerapkan aturan yang sama di server dan mode lokal, serta tidak mengekspos konten/file privat melalui snapshot. Dengan seluruh suite lulus, Phase 4 dinyatakan selesai dan baseline v4.0 siap dilanjutkan ke Phase 5–10.
