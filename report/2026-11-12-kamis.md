## 3. Absensi Karyawan — Fase 1 sampai Fase 3

### 3.1 Fase 1 — Role dan aturan server

- `users.role` diperluas menjadi `ENUM('admin','instruktur','peserta','karyawan')`.
- `staff_attendances` mendapat unique key `uq_staff_attendances_user_day_kind (user_id, attendance_date, kind)`, sehingga satu pengguna hanya dapat memiliki satu absen masuk dan satu absen pulang per hari.
- `api/install.php` memigrasikan ENUM dan merapikan duplikat lama sebelum menambah unique key.
- `staffAttendance.create` memakai **jam dan tanggal server** (`Asia/Jakarta`, disimpan UTC), mengabaikan nilai tanggal/jam/zona dari klien, mewajibkan GPS untuk semua role, serta menolak absen ganda dan absen pulang sebelum absen masuk.
- `staffAttendance.list` membatasi karyawan pada catatan sendiri; Admin dapat membaca catatan pengguna lain.
- `staffAttendance.delete` hanya untuk Admin, wajib alasan minimal 5 karakter, dan mencatat detail lama + alasan ke Audit Trail.
- Snapshot bootstrap tidak memuat koleksi absensi maupun foto.

### 3.2 Fase 2–3 — Modul bersama dan halaman karyawan

- `assets/js/attendance.js` (baru) memuat seluruh alur absensi: hero status harian, kamera + unggah foto, GPS wajib, metadata perangkat, aturan harian, riwayat pribadi, detail, modal berhasil, dan hapus oleh Admin.
- `admin/dashboard.html` tidak lagi menyimpan ±900 baris skrip inline; halaman memuat modul bersama tanpa perubahan tampilan/perilaku.
- `employee/attendance.html` (baru) memakai modul yang sama dengan role `karyawan`, tanpa sidebar admin dan tanpa tombol hapus.
- Routing role ditambahkan di `core.js`, `auth.js`, `config.js`, `api.js`, dan `ui.js`; `admin/users.html` menerima role **Karyawan** pada modal tambah/ubah, filter, dan badge.
- Mode lokal diselaraskan: GPS wajib, tanggal acuan `Asia/Jakarta`, duplikat harian ditolak, absen pulang harus setelah masuk, dan hapus hanya oleh Admin dengan alasan ≥5 karakter.

### 3.3 Aturan bisnis yang dikunci

- Hanya `admin` dan `karyawan` yang dapat mengakses absensi; instruktur dan peserta ditolak.
- GPS wajib untuk semua role pada data baru; data lama tanpa GPS tetap dapat dibaca.
- Tanggal, jam, dan zona waktu ditentukan server, bukan klien.
- Karyawan tidak dapat menghapus catatan; Admin dapat menghapus catatan mana pun dengan alasan yang tercatat.

## 4. Fase 4 — Sesi Diingat dan Satu Perangkat Aktif

### 4.1 Skema

- Tabel baru `user_devices` (tabel ke-38) menyimpan **hash SHA-256** token "ingat saya", label perangkat, user agent, IP, waktu dibuat/dipakai/kedaluwarsa, `revoked_at`, dan `revoked_reason`.
- `users.session_version` ditambahkan untuk membatalkan sesi PHP lama saat login baru, ganti password, akun dinonaktifkan, atau reset perangkat.
- Migrasi additive di `api/install.php` menjaga database lama tetap dapat ditingkatkan.

### 4.2 Alur token

- `auth.login` menerima `remember`; token acak 32 byte diterbitkan, hanya hash yang disimpan, dan cookie `elips_remember` dikirim `HttpOnly; SameSite=Lax; Secure` pada HTTPS dengan masa sliding 30 hari.
- Login baru menaikkan `session_version` dan mencabut token lama (`superseded`), sehingga hanya satu perangkat yang aktif.
- `auth.resume` memvalidasi cookie, membuat sesi PHP, merotasi token (`rotated`), dan memperpanjang masa berlaku.
- Pemakaian ulang token hasil rotasi mencabut **semua** perangkat pengguna (`reuse`), menaikkan `session_version`, dan menulis audit.
- `auth.logout` mencabut token perangkat saat ini (`logout`); `user.resetDevice` (Admin) mencabut semua token pengguna (`admin`).
- Ganti password dan penonaktifan akun mencabut seluruh token (`security`).
- Rate limit 10 percobaan gagal per 60 detik per IP+email (`auth.login`) atau per hash token (`auth.resume`).

### 4.3 Frontend

- `login.html`: checkbox **"Ingat saya di perangkat ini"** (aktif secara default).
- `auth.js`/`api.js`: `resumeSession()` dan fallback pada `requireRole`; `auth.resume` dipanggil otomatis setelah bootstrap tanpa sesi.
- `admin/users.html`: tombol **Reset Perangkat** per pengguna dengan konfirmasi.
- Mode lokal tidak memakai token perangkat; Reset Perangkat hanya mencatat audit demo.

## 5. Fase 5 — PWA dan Mode Offline

### 5.1 Aset PWA

| File | Fungsi |
|---|---|
| `manifest.webmanifest` | `start_url` halaman absen, `scope` root, `display: standalone`, warna tema, ikon 192/512 dan maskable, pintasan |
| `assets/icons/` | Enam PNG tanpa dependensi: `icon-192`, `icon-512`, `icon-maskable-192`, `icon-maskable-512`, `apple-touch-icon` 180, `favicon-32` |
| `sw.js` | Service worker **network-first**; halaman HTML aplikasi dan `/api/` tidak pernah di-cache; hanya `offline.html` + ikon di-precache |
| `assets/js/pwa.js` | Registrasi service worker, `skipWaiting` + `clients.claim`, reload sekali saat versi baru, banner Android, sheet iOS, penolakan 7 hari, bilah offline |
| `offline.html` | Halaman offline mandiri tanpa bundle aplikasi, dengan tombol muat ulang |

### 5.2 Perilaku

- Aplikasi terpasang membuka halaman absen sebagai `start_url` dan berjalan standalone.
- Strategi network-first memastikan perubahan file langsung terlihat tanpa menghapus cache manual.
- Simpan absensi saat offline ditolak dengan pesan yang jelas.
- Seluruh **30 halaman aplikasi** memuat manifest, `theme-color`, meta mobile/apple, favicon, apple-touch-icon, dan `pwa.js` (`defer`); `offline.html` sengaja berdiri sendiri.

## 6. Rekap Absensi Karyawan untuk Admin

### 6.1 Halaman dan navigasi

- Halaman baru `admin/attendance-recap.html` (halaman aplikasi ke-29) berjudul **Rekap Absensi Karyawan**.
- Menu **Rekap Absensi** ditambahkan setelah **Laporan** pada seluruh 12 sidebar admin.
- Filter: rentang tanggal, karyawan (default "Semua staf"), dan role (Semua/Karyawan/Admin).
- Empat kartu ringkasan: **Staf Absen**, **Hari Tercatat**, **Absen Lengkap**, dan **Belum Lengkap**.
- Tabel 7 kolom: Tanggal, Karyawan, Masuk, Pulang, Durasi, Lokasi, Status.
- Tombol **Muat Ulang**, **Bulan Ini**, dan **Ekspor CSV**.

### 6.2 Backend

- Aksi baru `staffAttendance.recap` (aksi API ke-95) **khusus Admin**.
- Default rentang: awal bulan berjalan sampai hari ini menurut `Asia/Jakarta`.
- Validasi: tanggal awal tidak boleh setelah tanggal akhir; rentang maksimal 366 hari.
- Filter `userId` dan `role`; respons tidak menyertakan data foto agar ringan.
- Instruktur/peserta ditolak guard akses, dan karyawan ditolak guard khusus rekap meskipun boleh mengakses absensi.

### 6.3 Modul klien dan ekspor

- `assets/js/staff-recap.js` (baru, modul JS ke-22) mengekspos `ELIPS.staffRecap` (`init`, `refresh`, `exportCsv`, `aggregate`, `statusLabel`).
- Agregasi per karyawan per hari dengan status `lengkap`, `belum_pulang`, atau `tanpa_masuk`.
- Mode lokal menghitung rekap dari `elips_staffAttendances` yang di-join dengan data pengguna, memakai aturan dan label yang sama dengan server.
- Ekspor CSV memakai BOM UTF-8, seluruh sel dikutip, dan nama file mengikuti rentang tanggal yang dipilih.

### 6.4 Dokumentasi

- `prd.md`, `log.md`, `erd.md`, dan `PRD_karyawan.md` diperbarui untuk fitur rekap, jadwal shift, surat menyurat, dan angka cakupan terbaru.

## 7. Jadwal Shift Karyawan untuk Admin

### 7.1 Halaman dan navigasi

- Halaman baru `admin/shifts.html` (halaman aplikasi ke-30) berjudul **Jadwal Shift Karyawan**.
- Menu **Shift Karyawan** ditambahkan setelah **Rekap Absensi** pada seluruh 13 sidebar admin.
- Filter: rentang tanggal (default seluruh bulan berjalan), karyawan, dan jenis shift; tombol **Bulan Ini** mengembalikan rentang awal.
- Empat kartu ringkasan: **Total Shift**, **Pagi**, **Sore**, dan **Custom**.
- Tabel shift menampilkan tanggal, karyawan, jenis, jam, catatan, dan aksi ubah/hapus; shift yang melewati tengah malam ditandai `+1 hari`.
- Modal tambah/ubah berisi karyawan, tanggal, jenis shift, jam mulai/selesai, dan catatan. Preset Pagi/Sore mengisi jam otomatis dan mengunci input; Custom membuka input jam manual.

### 7.2 Backend dan skema

- Tabel baru `staff_shifts` (tabel ke-38) dengan kolom `id`, `user_id`, `shift_date`, `shift_type` (`pagi`/`sore`/`custom`), `start_time`, `end_time`, `note`, `created_by`, `created_at`, dan `updated_at`.
- Unique key `uq_staff_shifts_user_date (user_id, shift_date)` menjaga satu shift per karyawan per tanggal; FK `user_id` CASCADE dan `created_by` SET NULL.
- Aksi baru `staffShift.list`, `staffShift.save`, dan `staffShift.delete` (aksi API ke-96–98) **khusus Admin**.
- Default rentang daftar adalah seluruh bulan berjalan, maksimal 366 hari; tanggal awal setelah tanggal akhir ditolak.
- `staffShift.save` menormalisasi jam `HH:MM`, mengabaikan jam klien untuk preset, menolak jam mulai = selesai, duplikat tanggal, pengguna nonaktif, dan role selain `admin`/`karyawan`.
- Shift **tidak** dimasukkan ke snapshot bootstrap; data hanya dibaca lewat `staffShift.list`.

### 7.3 Modul klien dan audit

- `assets/js/shift-schedule.js` (baru, modul JS ke-23) mengekspos `ELIPS.shiftSchedule` (`init`, `refresh`, `presets`).
- Mode lokal memakai key `elips_staffShifts` dengan validasi konflik tanggal, preset, dan jam Custom yang sama.
- Setiap create/update/delete mencatat audit entitas `staff_shift` dengan aktor, karyawan, tanggal, jam, dan catatan.
- Preset: **Pagi** `08:00–16:00`, **Sore** `16:00–00:00`.

## 8. Surat Menyurat untuk Admin

### 8.1 Halaman dan navigasi

- Halaman baru `admin/letters.html` (halaman aplikasi ke-31) berjudul **Surat Menyurat**.
- Menu **Surat Menyurat** ditambahkan setelah **Shift Karyawan** pada seluruh 13 sidebar admin lainnya; total 14 halaman admin kini memiliki tautan yang sama.

- Empat kartu ringkasan: **Total Surat**, **Surat Masuk**, **Surat Keluar**, dan **Selesai** mengikuti hasil filter.
- Tabel menampilkan jenis, nomor/perihal, rute pengirim → penerima, tanggal surat, sifat, status, dan aksi detail/ubah/hapus.
- Modal tambah/ubah memuat jenis surat, nomor, perihal, pengirim, penerima, tanggal surat, tanggal diterima/dikirim, kategori, sifat, status, ringkasan, tautan lampiran, dan catatan. Modal detail menampilkan seluruh field beserta pembuat.

### 8.2 Backend dan skema

- Surat **tidak** dimasukkan ke snapshot bootstrap; data hanya dibaca lewat `letter.list`.

### 8.3 Modul klien dan audit

- `assets/js/letter-archive.js` (baru, modul JS ke-24) mengekspos `ELIPS.letterArchive` (`init`, `refresh`, `directionLabel`, `safeAttachmentUrl`).
